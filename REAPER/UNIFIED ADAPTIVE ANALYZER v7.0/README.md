# 🎚️ UNIFIED ADAPTIVE ANALYZER v7.0: Automated Vocal Leveling & Gain-Riding Pipeline

**UNIFIED ADAPTIVE ANALYZER v7.0** is a high-performance, precision audio engineering toolkit designed to automate vocal leveling (gain riding) through an intelligent decouple-and-render architecture. By separating heavy psychoacoustic audio analysis from target execution, this pipeline allows you to analyze your vocal stems once and instantly render adjustments—either directly as a **DAW automation envelope** or as an **offline sample-accurate audio render** at any sample rate (44.1k, 48k, 96k, 192k).

---

## 🛠️ The Three Core Scripts

The v7.0 release consists of three dedicated scripts forming a unified workflow:

1. **`UNIFIED_ADAPTIVE_ANALYZER.v7.0.py` (The Analyzer)**
   * Streams large audio files in safe 1-second chunks.
   * Performs fast polyphase downsampling to **48 kHz** for rapid windowed DSP calculations.
   * Computes psychoacoustic metrics (RMS, Peak, Momentary/Short-Term/Integrated LUFS) using EBU-compliant windows.
   * Applies **Crest-Factor Intelligence**, **Silence/Breath Gating**, and **One-Pole IIR Smoothing** to output a deterministic, frame-accurate CSV log.

2. **`UNIFIED_ADAPTIVE_ANALYZER.v7.0-OFFLINE.RENDERER.py` (The Offline Render Engine)**
   * Bypasses the DAW entirely for fast trial-and-error processing.
   * Reads the pre-computed analysis CSV generated by `LYZER`.
   * Maps 10 ms control frames back onto your **original, full-resolution master stem** via linear interpolation.
   * Applies sample-accurate gain changes and exports a pristine 24-bit processed WAV file in seconds.

3. **`UNIFIED_ADAPTIVE_ANALYZER.v7.0-EnvelopeWriter.v7.0.lua` (The REAPER Automation Writer)**
   * Integrates directly into **REAPER (DAW)**.
   * Scans the selected single track for its **Trim Volume** envelope.
   * Translates decibel gain values into REAPER’s non-linear internal fader scaling.
   * Programmatically draws, sorts, and populates thousands of smooth automation points in real time.

## ⚙️ User-Defined Analysis Options (`UNIFIED_ADAPTIVE_ANALYZER.v7.0.py`)

The analyzer features robust configuration flags to tune the leveling behavior precisely to your performance:

* **`TARGET_LUFS`** *(default: `-18.0`)*: The target loudness threshold the engine drives your vocal toward.
* **`MAX_BOOST_DB` / `MAX_CUT_DB`** *(default: `+6.0` / `-6.0`)*: Hard ceilings controlling how far upward or downward the automatic gain adjustment can swing.
* **`SILENCE_RMS_DB` & `BREATH_RMS_DB`** *(default: `-50.0` / `-40.0`)*: Gating thresholds that prevent the script from aggressively boosting quiet background noise, room tone, or breaths.
* **`CF_TARGET_DB`, `CF_HARD_DB`, etc.**: Crest-factor behavior parameters that automatically scale back gain changes on sharp transients or percussive sibilance to avoid pumping artifacts.
* **`SMOOTHING_ALPHA`** *(default: `0.3`)*: Controls the one-pole IIR musical glide filter, ensuring volume changes transition smoothly without mechanical stepping or zipper noise.

## 📊 Anatomy of the Analysis CSV (`-v7.0-ANALYSIS.csv`)

The CSV output file serves as a universal interchange format containing two header rows (human-readable labels followed by machine keys) and subsequent data lines sampled every **10 ms (`STEP_MS`)**:

| Column Index | Header Key | Description |
| :--- | :--- | :--- |
| **1** | `t_proj / t_loc` | Project / local timeline timestamp in seconds. |
| **3–4** | `s_start / s_end` | Absolute sample index boundaries for the analysis window. |
| **5** | `RMS_dBFS` | Root Mean Square energy level within the window. |
| **6** | `Peak_dBFS` | True peak amplitude level in dBFS. |
| **7** | `M_LUFS` | Momentary LUFS (400 ms centered EBU window). |
| **8** | `ST_LUFS` | Short-Term LUFS (3,000 ms centered window). |
| **9** | `Int_LUFS` | Cumulative running integrated LUFS. |
| **10** | **`Gain_dB`** | **The final computed and smoothed gain adjustment in decibels.** |
| **11** | `CrestFactor_dB` | Dynamic range ratio between peak and RMS (`Peak - RMS`). |

## 🔬 Beyond Vocal Leveling: Other Audio Processing Ideas for the CSV

Because the analysis CSV provides a time-synced, high-resolution stream of dynamic behavior (`RMS`, `Peak`, `LUFS`, `Crest Factor`, and recommended `Gain_dB`), **the CSV data can easily power entirely different audio processing pipelines** outside of this specific project:

1. **Sidechain Ducking / Music Bed Control (`Music Ducking automation`)**
   * Feed the vocal CSV into a script that processes an instrumental backing track. Wherever the vocal's `Gain_dB` or `M_LUFS` increases, dynamically dip the instrumental track inversely to create a transparent, human-paced vocal ducking curve.
2. **Automated Dynamic EQ or Multiband Expansion**
   * Use the `CrestFactor_dB` column to identify hyper-transient sections. A script could read the CSV and trigger a dynamic EQ or transient shaper only when transient density crosses a threshold, saving manual node automation.
3. **Automated Visualizers / Video Lighting Scripts**
   * Map the `RMS_dBFS` or `Peak_dBFS` timeline columns directly to DMX lighting fixtures, MIDI control change (CC) data, or video motion graphics keyframes to create reactive lyric videos or light shows driven by the vocal performance.
4. **Data-Driven Limiter / Maximizer Drive**
   * Feed the running `Int_LUFS` and `Peak_dBFS` into an offline mastering limiter script to automatically drive input gain higher during quiet vocal passages and pull back during dense choruses.
